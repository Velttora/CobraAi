    - `decryptSecretBundle` with a `keyVersion` that has no configured env var throws an error naming the missing variable

    - Two `encryptSecretBundle` calls on identical input produce different ciphertext (random IV per call)

  <action>
    Create `packages/utils/src/crypto/envelope-encryption.ts` using Node's built-in `node:crypto` (`randomBytes`, `createCipheriv`, `createDecipheriv`) — do NOT add any npm dependency.

    Constants: `IV_LENGTH = 12` (96-bit, GCM-recommended), `AUTH_TAG_LENGTH = 16`, algorithm string `"aes-256-gcm"`.

    Key resolution: a private `resolveKey(keyVersion: number): Buffer` reads `process.env[\`ENCRYPTION_KEY_V${keyVersion}\`]`, base64-decodes it, and throws `Error("No encryption key configured for keyVersion=N (expected ENCRYPTION_KEY_VN)")` when absent and `Error("ENCRYPTION_KEY_VN must decode to 32 bytes for AES-256")` when the decoded length is not 32. Never log, never include the key or plaintext in any thrown message.

    `currentKeyVersion()` reads `ENCRYPTION_KEY_VERSION`, defaults to `1`.

    `encryptSecretBundle(secrets, keyVersion = currentKeyVersion())` serialises `secrets` with `JSON.stringify`, encrypts, and returns `{ ciphertext: Buffer.concat([iv, encrypted, authTag]), keyVersion }`. `decryptSecretBundle(ciphertext, keyVersion)` slices `iv = ciphertext.subarray(0, 12)`, `authTag = ciphertext.subarray(ciphertext.length - 16)`, `body = ciphertext.subarray(12, ciphertext.length - 16)`, calls `decipher.setAuthTag(authTag)` before `final()`, and `JSON.parse`s the result.

    `lastFour(value)` returns the trailing 4 characters, or the whole string when it is shorter than 4.

    Export all four functions plus the `EncryptedSecret` type from `packages/utils/src/index.ts`, following the existing grouped `export { ... } from "./module"` style used there for `./validation` and `./promises`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application process → Postgres | Ciphertext crosses here; the database is a lower-trust store than process memory |
| Process env → application | The master key enters here; anything that leaks env or logs leaks every tenant credential |
| Database dump / backup → operator | A stolen dump must not yield usable credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure | `tenant_integrations.secrets_cipher` at rest | mitigate | AES-256-GCM with a 32-byte env-sourced key; ciphertext-only column, no plaintext mirror column exists in the schema |
| T-08-01b | Tampering | ciphertext row modified directly in Postgres | mitigate | GCM auth tag verified on every decrypt; tamper test asserts a thrown error, never a silent wrong value |
| T-08-01c | Information Disclosure | master key in error messages / logs | mitigate | `resolveKey` throws messages naming only the env-var name, never its value; no `console.log`/`logger` call in the crypto module |
| T-08-02 | Information Disclosure | `secrets_meta` JSON column | mitigate | Column contract restricted to `lastFour` + `savedAt` per field (D-26); the value itself is never written there — enforced by the resolution service in plan 08-03 |

| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable in this plan: zero new dependencies are added (Node built-in `crypto` only) |
