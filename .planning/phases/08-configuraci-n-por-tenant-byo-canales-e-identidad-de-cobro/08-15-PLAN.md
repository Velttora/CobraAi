<objective>
Give the tenant one place to define its commercial identity — name, logo, contact details and legal signature — and inject it into every debtor-facing surface: WhatsApp template variables, the email signature, the voice agent's spoken introduction and the LLM agent's system prompt.

Purpose: `variables.empresa` already exists in the WhatsApp renderer but falls back to `"su gestor de cobranza"` because nothing ever fills it from the tenant. The whole point of this phase is that communication goes out in the tenant's name; a per-tenant number that still says "su gestor de cobranza" defeats it. UI-SPEC assumption A-05 also found `SignatureEditor` already editing the same company fields, which must become a mirror of this single source rather than a second copy that silently diverges.
Output: `BrandIdentity` in `@cobrai/utils`, a tenant endpoint to edit it, and injection into all four channels.
</objective>

```typescript
// packages/utils/src/brand-identity.ts
export const EMPRESA_FALLBACK = "su gestor de cobranza";

export interface BrandIdentity {
  commercialName: string | null;   // fills variables.empresa
  logoUrl: string | null;
  supportPhone: string | null;
  supportEmail: string | null;
  website: string | null;
  address: string | null;
  legalName: string | null;        // razón social
  taxId: string | null;            // NIT
  legalNotice: string | null;      // aviso legal
}

export const EMPTY_BRAND_IDENTITY: BrandIdentity;
export function sanitizeBrandIdentity(input: unknown): BrandIdentity;
/** Template/prompt variables derived from the identity, with the existing fallback applied. */
export function resolveBrandVariables(identity: BrandIdentity): {
  empresa: string;
  empresa_telefono: string;
  empresa_correo: string;
  empresa_sitio_web: string;
  empresa_razon_social: string;
  empresa_nit: string;
  empresa_aviso_legal: string;
};
```
Endpoint: `PATCH /api/v1/tenant/brand-identity` (admin) → `TenantProfile`, which gains a `brandIdentity: BrandIdentity` field.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tenant-supplied brand fields → debtor-facing HTML email | Tenant input is rendered into HTML sent to third parties |
| Tenant-supplied brand fields → LLM system prompt | Tenant input is concatenated into a prompt that steers agent behaviour |
| `Tenant.settings` → tenant profile response | `settings` is serialized wholesale to the profile |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-15a | Tampering | `javascript:` or `data:` URL in `logoUrl`/`website` rendered into an HTML email | mitigate | `sanitizeBrandIdentity` nulls any URL not starting with `http://` or `https://`; asserted by test. The existing `escapeHtml` in `renderEmailLayout` remains the second layer |
| T-08-15b | Tampering | prompt injection through a brand field steering the LLM agent | mitigate | Brand values are interpolated into a fixed, parameterized prompt builder rather than concatenated ad hoc at the call site; the fields are short identity strings, and the agent's tool surface is unchanged by this plan. Residual risk accepted and recorded |
| T-08-15c | Information Disclosure | credentials leaking into `Tenant.settings` alongside brand identity | mitigate | `sanitizeBrandIdentity` returns only the nine declared fields and drops unknown keys, so a caller cannot smuggle arbitrary data into `settings` through this endpoint |
| T-08-15d | Elevation of Privilege | a non-admin changing the identity every debtor sees | mitigate | `assertAdmin` on `updateBrandIdentity`, matching the other tenant write endpoints |
| T-08-15e | Spoofing | a tenant impersonating another company by setting its name | accept | Out of scope for this phase: brand identity is self-asserted, exactly as the existing `Tenant.name` and email signature already are. Provider-level identity (WABA verification, domain authentication) is the real control and is enforced in plans 08-07 and 08-11 |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: no package is installed in this plan |
</threat_model>
