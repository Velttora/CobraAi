<objective>
Move the three channel adapters off constructor-cached, process-global clients onto per-request tenant credential resolution; kill the simulate-on-missing-credential pattern except behind an explicit flag that cannot be on in production; and route email replies to the tenant's own domain.

Purpose: the current adapters read `ConfigService` once at boot and cache a client — architecturally incompatible with credentials that are per tenant and can rotate at runtime. Worse, all five adapters return `status: "sent"` when a credential is missing (RESEARCH.md Pitfall 3), which under BYO would mean phantom sends inflating delivery metrics and consuming the Ley 1266 contact quota for contacts that never happened. D-17 requires the flag plus a boot guard plus a DB marker. D-22 removes the fixed `reply@reply.fogging.org`.
Output: four refactored adapters, a boot guard, `simulated` on the port results and on the persisted rows, and per-tenant reply addressing.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tenant credential store → outbound provider call | A resolution bug sends tenant A's message with tenant B's identity |
| Environment configuration → runtime behaviour | A single env var decides whether real messages are sent |
| Adapter result → compliance metrics and Ley 1266 quota | A fake success corrupts a legally meaningful counter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | Spoofing | simulation enabled in production, reporting phantom sends as delivered | mitigate | `assertSimulationNotInProduction` runs before `NestFactory.create`; the process refuses to start. Asserted by an isolated guard test, no Nest boot required |
| T-08-10b | Spoofing | one tenant's message sent from another tenant's number or domain | mitigate | Client and sender are built per call from `resolveByChannel(input.tenant_id, ...)`; a test asserts two tenants produce two distinct SDK clients with their own SIDs |
| T-08-10c | Repudiation | a simulated send indistinguishable from a real one in the audit trail | mitigate | `simulated` flows from the adapter result onto `Contact.simulated` and `Message.simulated`; asserted by test |
| T-08-10d | Information Disclosure | a stale cached client keeping a revoked credential alive after rotation | mitigate | No constructor-cached client remains; the only cache is the 30s TTL in `TenantIntegrationService`, invalidated on upsert (plan 08-03) |
| T-08-10e | Information Disclosure | debtor replies landing on the platform's shared domain instead of the tenant's | mitigate | Reply-To derived from the tenant's `replyDomain`; the fixed constant is deleted and its absence grep-asserted |
| T-08-10f | Denial of Service | a tenant without DNS configured losing email entirely | mitigate | Missing `replyDomain` omits the key rather than failing the send — outbound-only is the documented degraded state (D-22) |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: no package is installed in this plan |
