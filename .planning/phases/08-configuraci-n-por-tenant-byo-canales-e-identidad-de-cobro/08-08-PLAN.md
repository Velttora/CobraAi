<objective>
Build the five API-backed payment gateway adapters — Stripe, Mercado Pago, Wompi, PayU Colombia and ePayco — each accepting the tenant's own credentials per call rather than reading a platform-global key.

Purpose: D-06 makes payments strictly BYO. Stripe lists debt collection agencies as prohibited and does not support Colombia for Connect; Mercado Pago prohibits third parties processing payments for collections companies. There is no managed path and money is never centralized under the platform account. The existing `GatewayService` reads every key from `ConfigService` and fakes a successful checkout when a key is missing — under BYO that would mean a debtor receiving a link to nowhere.
Output: a `GatewayAdapter` contract plus five provider implementations with unit tests over mocked HTTP. Wiring these into dispatch and rewriting the read sites is plan 08-09.
</objective>

export type CheckoutSession = {

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Service → provider API | Tenant payment credentials leave the process here |
| Adapter → debtor-facing URL | Anything placed in a checkout URL is visible to the debtor |
| Provider error text → application logs and UI | Provider messages are shown verbatim to the tenant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06 | Information Disclosure | tenant gateway key in logs, thrown messages or a checkout URL | mitigate | Every adapter has a test asserting the secret value appears in no logger call and no thrown message; only fields the provider's documented contract requires go into a URL |
| T-08-06b | Spoofing | a fabricated sandbox checkout URL sent to a real debtor | mitigate | The `if (!apiKey) { ...sandbox... }` branch is deleted, not ported; absent credentials throw, asserted per adapter |
| T-08-06c | Tampering | signature construction drifting between checkout creation and webhook verification | mitigate | Each formula is documented in a comment at the point of use, and plan 08-12 verifies against the same documented construction |
| T-08-06d | Tampering | wrong amount unit causing a 100x under- or over-charge | mitigate | Per-adapter comment stating the unit plus a test asserting the exact outgoing value for a known input |
| T-08-06e | Elevation of Privilege | one tenant's credentials used for another tenant's checkout | mitigate | Adapters are stateless and hold no credential; every credential arrives as a call argument resolved by `TenantIntegrationService` (tenant-keyed, plan 08-03) |
| T-08-SC | Tampering | npm install of `stripe` | mitigate | slopcheck rated `[OK]` in RESEARCH.md's Package Legitimacy Audit, but Assumption A6 labels the identity `[ASSUMED]`, so Task 1 is a blocking human verification against the npm registry page before install; not auto-approvable |
</threat_model>
