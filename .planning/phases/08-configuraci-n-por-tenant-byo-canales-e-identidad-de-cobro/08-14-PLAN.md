</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → api-gateway | Clerk-authenticated; the gateway injects `x-tenant-id` and `x-user-role` |
| api-gateway → service-notifications | Header-trusting internal hop; the service must still enforce role itself |
| Service → HTTP response | The boundary D-26 protects: a secret must be structurally unable to cross it |
| Tenant-supplied template/domain strings → persisted config | Untrusted input that later produces debtor-facing URLs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-08 | Information Disclosure | plaintext secret in an API response | mitigate | Every response goes through `TenantIntegrationService.toView`, which derives `secrets` from `secretsMeta` (lastFour only); asserted against `JSON.stringify` of the response, not field-by-field |
| T-08-14b | Elevation of Privilege | a non-admin writing or rotating credentials | mitigate | `assertAdmin` at the top of every write method in the service layer, not only at the gateway — the service is protected even if called directly |
| T-08-14c | Elevation of Privilege | cross-tenant read of integrations or blocked debts | mitigate | Every query is keyed on `ctx.tenantId` from the gateway-injected header; a cross-tenant isolation test covers the blocked-debts query |
| T-08-14d | Tampering | a tenant saving a non-TLS or attacker-controlled external payment template | mitigate | `validateExternalLinkTemplate` enforced server-side on save, rejecting anything not `https://`; browser validation is a convenience, not the control |
| T-08-14e | Tampering | SQL injection through the audit-log JSON predicate | mitigate | Prisma tagged-template `$queryRaw` only; `$queryRawUnsafe` is grep-asserted absent |
| T-08-14f | Information Disclosure | webhook URL exposed to a non-admin caller | accept | The webhook URL contains an opaque token that authenticates the provider callback. Reads are not admin-gated (matching the existing tenant profile endpoint), so any authenticated member of the tenant can see it. Scope is the same tenant, and the token grants nothing beyond delivering a signed webhook for that tenant |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: no package is installed in this plan |
