<objective>
Build the single place in the codebase that turns `(tenantId, provider)` into usable credentials — replacing the constructor-cached, process-global client pattern that all five adapters use today.

Purpose: D-01 requires managed and BYO integrations to resolve identically; the only difference is how they were provisioned. D-11 requires a live health check at save time. D-26 requires the API to be structurally incapable of returning a plaintext secret. All three converge on one service, and both `service-notifications` and `service-payments` need it — so it lives in a shared workspace package following the `packages/compliance` precedent (plain classes, wired per app with a NestJS factory provider), not inside one service.
Output: new `@cobrai/integrations` workspace package exporting `TenantIntegrationService`, the shared provider/channel/status contracts, and a `verifyCredentials` dispatcher with the three communication-channel verifiers implemented.
</objective>

import type { IntegrationProvider, IntegrationMode, IntegrationStatus } from "@cobrai/db";

export type IntegrationChannel = "whatsapp" | "voice" | "email" | "payments";

export const CHANNEL_PROVIDERS: Record<IntegrationChannel, IntegrationProvider[]>;

  id: string;
  tenantId: string;
  provider: IntegrationProvider;
  mode: IntegrationMode;
  status: IntegrationStatus;
  publicConfig: Record<string, string>;
  secrets: Record<string, string>;
  webhookToken: string | null;
  verifiedAt: Date | null;

export interface IntegrationView {
  provider: IntegrationProvider;
  channel: IntegrationChannel;
  mode: IntegrationMode;
  status: IntegrationStatus;

  failureMessage: string | null;

  secrets: SecretMeta[];

  ok: boolean;

}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres → process memory | Ciphertext becomes plaintext credentials here; anything cached after this point is a live secret |
| In-process cache → request handler | A cache keyed wrongly serves tenant A's credentials to tenant B |
| Service → provider API | Credentials leave the process here; only over TLS, never logged |
| Service → HTTP response | The boundary D-26 protects: a secret must be structurally unable to cross it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Information Disclosure | `resolve()` returning a stale/unverified credential | mitigate | `status !== "verified"` returns `null`; asserted by a test per non-verified status value |
| T-08-03b | Elevation of Privilege | short-TTL cache serving cross-tenant credentials | mitigate | Cache key is `${tenantId}:${provider}`; a dedicated test proves two tenants get two lookups and two results |
| T-08-03c | Information Disclosure | plaintext secret in an API response | mitigate | `toView` derives `secrets` from `secretsMeta` (lastFour only) and is the single serialization path; test asserts the plaintext is absent from the serialized view |
