<objective>
Wire the gateway adapters into a tenant-config-driven dispatcher, add the two no-integration payment options (`external_link` with its `{monto}`/`{ref}`/`{nombre}` template, and `transfer`), and make saving payment credentials produce a live provider verdict.

Purpose: D-06 (BYO only), D-13 (external link as a template), D-14 (no webhook means manual reconciliation, not a silent success), D-11 (synchronous verification on save). This is where the country-based `pickGateway` heuristic dies: under BYO the tenant's own `TenantIntegration` is the only valid dispatch key.
Output: `resolveExternalLinkTemplate` in `@cobrai/utils`, the `external_link` and `transfer` adapters, a rewritten `GatewayService`, updated `PaymentLinksService` read/write sites, and five payment verifiers.
</objective>

**Placeholder-syntax collision, resolved deliberately (UI-SPEC assumption A-07).** D-13 mandates single-brace `{monto}`/`{ref}`/`{nombre}`. The existing template system in `packages/utils/src/template-variables.ts` and `apps/web/lib/template-preview.ts` uses double braces and names the reference variable `referencia`. The two systems stay separate: this plan adds a dedicated single-brace resolver for external payment links only, and must not touch `renderTemplatePreview` or `template-variables.ts`. Unifying them is a product decision outside this phase.
</context>

export interface ExternalLinkValues {

export interface ExternalLinkTemplateError { code: "not_https" | "no_reference" | "unknown_variable"; message: string; variable?: string; }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Debtor (unauthenticated) → `POST /v1/payments/checkout/:token` | A public endpoint; its body was previously able to change which gateway processed the payment |
| Tenant-authored template → debtor-facing URL | The tenant controls a URL string that is sent to debtors |
| Service → provider verification endpoints | Tenant payment credentials leave the process here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-09a | Tampering | debtor-supplied provider on the public checkout endpoint | mitigate | Dispatch reads only the stored `link.provider`; the request-body value is ignored, asserted by test |
| T-08-09b | Information Disclosure | unencoded debtor name or reference breaking out of the external link query string | mitigate | `resolveExternalLinkTemplate` runs every value through `encodeURIComponent`, asserted by test |
| T-08-09c | Spoofing | a tenant template pointing at a non-TLS or attacker-controlled endpoint | mitigate | `validateExternalLinkTemplate` rejects anything not starting with `https://`; enforced server-side on save in plan 08-14, not only in the browser |
| T-08-09d | Spoofing | a tenant with no configured method still receiving a plausible payment link | mitigate | Explicit `BadRequestException` at both the link-creation and checkout layers; no `transfer` fallback |
| T-08-09e | Information Disclosure | payment credential in a verifier error message | mitigate | Verifier messages carry only the provider's response body; a test asserts the secret never appears |
| T-08-09f | Repudiation | an external-link or transfer payment being treated as confirmed without evidence | mitigate | D-14: neither provider is in `WEBHOOK_CAPABLE_PROVIDERS`; a debtor claim produces a `promise_to_pay` pending confirmation, and reconciliation stays manual |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: no package is installed in this plan (`stripe` was gated in plan 08-08) |
</threat_model>
