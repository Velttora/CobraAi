<objective>
Make the cutover safe: copy the platform's current global credentials (`TWILIO_ACCOUNT_SID`/`TWILIO_AUTH_TOKEN`/`TWILIO_WA_FROM`, `SENDGRID_API_KEY`/`SENDGRID_FROM_EMAIL`, `MP_ACCESS_TOKEN`) into `TenantIntegration` rows for every tenant that already exists, so that when the adapters switch to per-tenant resolution in plan 08-09 nobody suddenly stops sending.

Purpose: D-18. Without this, the moment the adapters stop reading `ConfigService` every existing tenant has zero verified integrations, `channel_not_configured` fires for all of them, and every debt escalates to a human. New tenants deliberately start empty — the seed is a one-time bridge for pre-existing tenants only.
Output: an idempotent TypeScript data migration, its production runner, and tests proving re-running it is a no-op.
</objective>

**Why this is a TypeScript data migration and not a `.sql` migration file.** The project rule is that reference data and backfills ship as idempotent migrations, not seed scripts — `20260714130000_seed_colombia_holidays/migration.sql` is the precedent. That rule cannot be followed literally here: the rows must contain AES-256-GCM ciphertext produced by `@cobrai/utils`, and a `.sql` file can neither read `process.env` nor run the cipher. The repo already has an established pattern for exactly this case — `packages/db/src/backfill-escalations.ts` plus `infra/fly/run-prod-db-fix.sh` — and this plan follows it. The idempotency guarantee (`ON CONFLICT DO NOTHING`) is preserved in application form as a skip-if-exists check on `(tenantId, provider)`.
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Process env → database | Global platform credentials are copied into per-tenant rows here; a bug writes them in plaintext or to the wrong tenant |
| Operator shell → production database | A script that writes credentials for every tenant, run by hand |
| Script stdout → CI/terminal logs | Anything logged here may end up in a log aggregator |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06a | Information Disclosure | plaintext credential written to `secrets_meta` or logged | mitigate | Only `lastFour`/`savedAt` reach `secretsMeta`; a test asserts the plaintext is absent from both write arguments; no log statement interpolates a secrets object |
| T-08-06b | Tampering | seed overwriting a tenant's own configured credentials | mitigate | Skip-if-exists on `(tenantId, provider)` with `findUnique`; `upsert` is banned and grep-asserted |
| T-08-06c | Elevation of Privilege | partial run leaving some tenants seeded and others not, with the cipher failing midway | mitigate | Fail-fast encryption probe before the first Prisma write, exiting non-zero |
| T-08-06d | Tampering | production script run before its migrations or without the key | mitigate | Precondition banner naming both migration ids and `ENCRYPTION_KEY_V1`, plus a mandatory `si` confirmation gate |
| T-08-06e | Spoofing | a divergent second implementation of AES-256-GCM inside the `.cjs` runner | mitigate | The `.cjs` imports the crypto helper; a grep asserts no cipher primitive appears in it |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: no package is installed in this plan |
</threat_model>
