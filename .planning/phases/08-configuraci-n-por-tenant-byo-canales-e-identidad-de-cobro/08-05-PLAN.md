<objective>
Add `channel_not_configured` as a first-class compliance reason so that a tenant with no verified credentials for a channel stops sending through it — at the one choke point that already governs every send — and escalates to a human when no channel is left.

Purpose: D-16. STATE.md records two intentional `ComplianceService` lanes (`checkContact`/`checkBeforeSend` for proactive outreach, `isChannelEligible` for debtor-initiated replies) and states that any new code path calling a WhatsApp/voice/email adapter must pass through one of them. The configured-channel check therefore belongs in compliance, never in the adapters — putting it in an adapter would create the third, ungoverned lane the project has explicitly ruled out.
Output: the new reason in the type union, the gate in both compliance methods, the waterfall filtered by configured channels, and human escalation when nothing is configured.
</objective>
