<objective>
Provision the email channel: create a SendGrid subuser per tenant with its own scoped API key, authenticate the tenant's sending domain, expose the resulting CNAME records so the tenant can publish them, and re-check validation on demand — with a BYO path that skips provisioning entirely.

Purpose: D-03. Email must be signed by the tenant's own domain, which irreducibly requires the tenant to publish CNAME records in its DNS. D-22 depends on this: the reply domain the adapters use comes from here. D-11 requires the save to produce a verdict, and the DNS-pending state is a distinct third outcome that is neither success nor failure.
Output: `SendgridProvisioningService`, `EmailConnectService`, and the `pending_dns` lifecycle backing UI-SPEC's "DNS / CNAME (D-03)" state table.
</objective>

export interface SendgridSubuser { username: string; userId: number; apiKey: string; }

  validateDomain(subuserUsername: string, domainId: number): Promise<AuthenticatedDomain>;

}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Parent SendGrid account → tenant subuser | The parent key can act on every tenant; leaking it compromises all of them |
| Tenant-supplied domain string → SendGrid API | An untrusted value used to authenticate a sending domain |
| Provisioning output → database | A freshly minted subuser API key is written here |
| Persisted `publicConfig` → API response | `publicConfig` is returned unredacted to the tenant by design |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-05 | Information Disclosure | parent SendGrid API key in logs, errors or an API response | mitigate | Parent key read only in the provisioning service, never persisted per tenant, never in a thrown message; asserted by test. `publicConfig` carries no key |
| T-08-11b | Information Disclosure | subuser API key leaking through `publicConfig`, which is returned unredacted | mitigate | Key goes only into the encrypted `secrets` bundle; a test asserts it appears in no `publicConfig` argument |
| T-08-11c | Spoofing | a tenant authenticating a domain it does not control, then sending as someone else | mitigate | SendGrid only marks a domain valid once the CNAMEs are published in that domain's DNS, which requires control of it; the integration stays `pending_dns` until then and the adapter's `resolve` gates on `verified` |
| T-08-11d | Elevation of Privilege | domain authenticated at the parent level instead of the subuser's, so it silently applies to everyone | mitigate | Call shape taken from `08-PROVIDER-CONTRACTS.md`'s resolution of RESEARCH.md Open Question 2, not improvised (Pitfall 5) |
| T-08-11e | Information Disclosure | the generated subuser password persisting anywhere | mitigate | Generated with `randomBytes`, used once, never returned or logged; asserted by test |
| T-08-11f | Denial of Service | repeated connect attempts creating duplicate subusers and exhausting the account | mitigate | Deterministic username plus reuse-if-exists, asserted by test |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] — not applicable: SendGrid is called with raw `fetch`, no package is installed |
</threat_model>
